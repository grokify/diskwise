# Release Notes v0.2.0

**Release Date:** October 7, 2026

## Overview

v0.2.0 makes DiskWise's numbers trustworthy and adds the commands that
came out of using it on a real machine: checking free space for an OS
upgrade, comparing archives with their extracted copies, producing a
reviewable worklist, and sharing output without exposing paths. It also
ships the first MkDocs user guide.

DiskWise remains discovery-only: it never deletes, moves, or modifies
anything it finds.

## Installation

```bash
go install github.com/grokify/diskwise/cmd/diskwise@v0.2.0
```

## Breaking changes

- **`opportunities --json` now prints an object, not a bare array.** The
  findings are under `Opportunities`, alongside `Root`, `ScannedAt`,
  `ScanStatus`, `Stale`, and the size-cut and missing-path counts. This is
  the same shape `export` writes to `opportunities.json`, so there is one
  shape for opportunities output. Update scripts from `.[]` to
  `.Opportunities[]`.
- **`savings` no longer counts the `unknown` and `keep` tiers in its
  headline total.** In v0.1.0 "Potential savings" summed every tier,
  including large unexplained directories, which overstated what could be
  reclaimed. The per-tier lines are unchanged.
- **`savings`, `hotspots`, `savings --json` and `hotspots --json` gain
  fields** (`ScannedAt`, `ScanStatus`, `Stale`, and missing-path counts).
  Existing fields are unchanged.

## Features

### Totals that add up

Unexplained directories are now reported only at their outermost level, and
the bytes that other findings already account for (known caches, archives,
managed bundles) are subtracted from them. Tier totals can no longer exceed
what the scanned folder holds. `hotspots` applies the same rule.

### Results say how old they are

`savings`, `hotspots`, `opportunities`, `review`, and `export` show when
the covering scan finished and warn on stderr when it is more than a week
old. Findings whose paths no longer exist on disk (for example a cache you
cleaned after scanning) are marked `[missing]` and counted, so a removed
cache is not presented as a saving.

### App-managed bundles

Photos, Music, TV, iMovie, Final Cut, Logic, and GarageBand libraries and
sparse bundles are reported as `keep` instead of `unknown`, with advice to
manage them from the owning app. Only the outermost bundle is reported and
nothing inside it is reported separately.

### `pairs`: archives and their extracted copies

`diskwise pairs [path]` compares each `.tar`, `.tar.gz`, `.tar.bz2`, and
`.zip` that sits beside a same-named directory by file count and bytes
(`same`, `same_count`, `archive_has_more`, `dir_has_more`). For Photos
libraries it compares original media only, because the internal layout
changes between app versions. Contents are not hashed.

### `preflight`: free space for an upgrade

`diskwise preflight --need 50gib` reports capacity, available space, APFS
container free space, and Time Machine local snapshots, and exits non-zero
when the volume is short.

### `review` and `export`

`diskwise review --format md` writes a checkbox worklist grouped by tier.
`diskwise export --out DIR` writes `savings.json`, `opportunities.json`,
`hotspots.json`, and `review.md` (and `pairs.json` with `--pairs`), each
recording the root it covers. Both take `--min-size` (default `1mb`) and
state how many smaller findings they left out.

### Sharing safely

`--redact` shows the home directory as `~`. `--redact-prefix PATH`
(repeatable) replaces every path under a prefix, and the names and text
derived from it, with a stable opaque token. Available on `opportunities`,
`hotspots`, `savings`, `pairs`, `report`, `review`, and `export`.

### Scan transparency

A scan lists the directories it could not read and points to Full Disk
Access, instead of suggesting elevated permissions (which do not bypass
macOS privacy protections). Commands that default to the current directory
now say so on stderr.

### User guide

A Material-themed MkDocs site covers installation, every command, how
findings are classified, JSON output, known locations, and
troubleshooting. A workflow deploys it to GitHub Pages.

## Fixed

- An archive beside a same-named directory was called likely-safe on the
  name match alone. For plain tar and zip the detector now checks the
  archive against the directory: an archive that lists files the directory
  lacks is `review`, with the evidence in the reason.
- Plain `.tar` files were not recognized as archives by the archive and
  artifact-family detectors.

## Known limitations

- **The MCP server is still a skeleton.** `cmd/diskwise-mcp` registers no
  tools yet (roadmap Phases 4-5).
- **The index is a snapshot.** Missing-path detection catches findings
  whose paths were removed, but a path that still exists and has merely
  changed size is only caught by rescanning. Every result states when it was
  measured.
- **Purgeable space is not counted by `preflight`.** macOS does not expose
  it to the command line.
- **`pairs` compares counts and sizes, not contents.** `same` is strong
  evidence, not proof.
- **Redaction is prefix-based.** A sensitive name in a path outside the given
  prefixes is left as is.
- **Slower on large trees.** Reading tar and zip member lists to check
  extracted siblings roughly doubled `savings` on a ~10 million file home
  directory on a cold cache (about 1 to 2.5 minutes). Compressed archives
  are skipped in this check.
