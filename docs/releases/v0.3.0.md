# Release Notes v0.3.0

**Release Date:** October 7, 2026

## Overview

v0.3.0 replaces the separate savings, hotspots and opportunities outputs with
one **report document**: a single versioned JSON file that every report is
rendered from. A report can now be saved once, then rendered as HTML,
spreadsheet or Markdown on any machine, with no index, no scan, and no access
to the files, and redacted at render time for sharing.

DiskWise remains discovery-only: it never deletes, moves, or modifies
anything it finds.

## Installation

```bash
go install github.com/grokify/diskwise/cmd/diskwise@v0.3.0
```

## Breaking changes

- **`export` writes different files.** It now produces `report.json`,
  `report.html` and `review.md`. The separate `savings.json`,
  `opportunities.json`, `hotspots.json` and `pairs.json` are gone; their
  content is in `report.json` (the tier totals, the findings, and, with
  `--pairs`, the archive comparisons).
- **`report` omits small findings by default.** Findings under `1mb` are left
  out and the report states how many (use `--min-size 0` for everything).
  Tier totals still cover every finding.
- `opportunities`, `savings` and `hotspots` are unchanged, including their
  `--json` output.

## Features

### The report document

`diskwise report --format json` (and `export`, as `report.json`) writes the
document: the root, when it was measured, tier totals computed before any size
cut, an account of findings that have vanished from disk or been filtered out,
the findings, and optionally archive comparisons. `savings` is its tier totals
and `hotspots` is a selection of its findings, so each fact is stated once.

Properties are camelCase and the document has a generated JSON Schema:
`diskwise report --schema` prints it. Parsing is strict, so a typo or version
mismatch fails loudly instead of mis-rendering.

### Render a saved document anywhere

```bash
diskwise report --from report.json --format html --out report.html
diskwise report --from report.json --format md   --out review.md
diskwise report --from report.json --format xlsx --out report.xlsx
```

Rendering is deterministic: the same document always produces the same bytes.
The only time shown is when the data was measured, taken from the document and
never from the clock. `--redact` and `--redact-prefix` also work with
`--from`, so one saved document can produce a shareable copy.

### A fuller HTML report

The HTML report adds notices for stale, partial, vanished and filtered data;
tier totals that cover every finding; known heavy locations and large
unexplained directories; an archive-pair section; and the full sortable,
filterable findings table. It remains a single self-contained file with no
external resources.

### `report` and `review` options

`report` gains `--format md|json`, `--from`, `--min-size`, `--pairs` and
`--schema`. `review` gains `--from`.

### Changelog reference check

A test and a `Changelog References` workflow verify that every commit hash in
`CHANGELOG.json` is reachable from the branch, so changelog links cannot go
stale unnoticed.

## Hardened

- **Redaction scrubs whole directory paths in descriptive text.** Reports
  contain descriptive strings (a finding's reason, a scenario's description,
  an archive comparison's detail) alongside the structured path fields. When
  such text named a directory path under a `--redact-prefix`, only the prefix
  itself was replaced and the rest of the path stayed visible. A redacted
  prefix is now replaced together with whatever path continues from it. This
  was found with synthetic test text: none of the detectors shipped in v0.2.0
  writes text that names a directory above a redacted file, so v0.2.0 output
  was not affected in practice.

## Known limitations

- **The MCP server is still a skeleton.** `cmd/diskwise-mcp` registers no
  tools yet (roadmap Phases 4-5).
- **The index is a snapshot.** Removed paths are detected and marked, but a
  path that still exists with a new size is only caught by rescanning. Every
  report states when it was measured.
- **Purgeable space is not counted by `preflight`.** macOS does not expose it
  to the command line.
- **`pairs` compares counts and sizes, not contents.**
- **Redaction is prefix-based.** A sensitive name in a path outside the given
  prefixes is left as is.
- **Archive checks add time on large trees.** Reading tar and zip member lists
  to check extracted siblings roughly doubled `savings` on a very large home
  directory with a cold cache.
