# Release Notes v0.1.0

**Release Date:** August 22, 2026

## Overview

This is the initial release of DiskWise, a macOS storage-intelligence
CLI. DiskWise discovers what is actually consuming disk space —
attributed to meaningful entities like apps, databases, containers,
caches, and artifact families rather than raw paths — and classifies
what can be safely reclaimed by confidence and risk, rolled up into a
directly actionable, manual-deletion worklist.

V1 is discovery-only: DiskWise identifies and explains reclaimable
storage; it does not delete anything.

## Installation

```bash
go install github.com/grokify/diskwise/cmd/diskwise@v0.1.0
```

The MCP server binary (`cmd/diskwise-mcp`) is scaffolded but does not
yet register any tools — see [Known Limitations](#known-limitations).

## Features

### Scanner (`scan`)

A concurrent, priority-queue directory walker: `GOMAXPROCS` workers
pull from a shared max-heap ordered by already-counted direct byte
size (largest first), so the biggest subtrees resolve early. Hard
links are deduplicated by (device, inode) so they're never
double-counted, and both logical size and APFS allocated size
(`st_blocks × 512`) are recorded — the latter is what makes sparse
files like Docker's `Docker.raw` report their real on-disk footprint
instead of their apparent size.

### Index (`index`)

Every scan is persisted into a disposable, rebuildable SQLite index
(`modernc.org/sqlite`, pure Go, no cgo) with subtree byte rollups and
a `rescan <path>` command that replaces one subtree and propagates the
byte delta to its ancestors.

### Knowledge registry (`knowledge`)

A registry of adapters for known heavy-storage locations — Docker
Desktop, Xcode, Homebrew, Go, Node, Python, local AI models, iOS
backups, browsers, Trash — each contributing relevance probes,
expanded data paths (used to prioritize scanning), and a default
action class.

### Policy engine (`policy`)

`Evaluate()` enforces two rules no detector can override: managed data
(databases, containers, VMs, applications) is structurally capped at
`backup_then_delete`, and `safe_delete` requires at least 0.8
detection confidence or it's downgraded to `likely_safe`. A proposal
can only become more conservative here, never less.

### Detectors (`detect`)

Four detectors read the completed index and propose what its bytes
mean, each claiming disjoint territory so nothing is ever
double-counted:

- **KnownLocationDetector** — registry hits
- **ArchiveInstallerDetector** — extraction-sibling and installed-app
  evidence for standalone `.dmg`/`.pkg`/`.zip`/`.tar.gz`/etc.
- **ArtifactFamilyDetector** — repeated downloaded versions of the
  same artifact (e.g. five `elasticsearch-*.tar.gz` versions), with
  keep-newest/remove-all scenarios
- **LargeUnexplainedDetector** — large directories no other detector
  claims, reported at zero confidence rather than guessed at

### Directory rollup (`rollup`)

`Collapse()` bubbles a finding's covered paths up to the smallest set
of directories that exactly covers the same bytes, cascading through
multiple levels where every child is covered, and leaving a partially
covered ("mixed") directory decomposed into individual paths instead
of over-claiming it.

### Reports (`report`)

`diskwise report` renders `opportunities` into a self-contained,
sortable/filterable HTML file (vendored table script, `file://` links,
no CDN dependency) or an `.xlsx` workbook (frozen header row,
autofilter) via `excelize`.

### Insights JSON IR (`insights`)

`insights.Report` is a JSON intermediate representation an LLM agent
fills out after reading DiskWise's raw findings and recognizing
patterns the deterministic detectors can't yet — duplicate migration
backups, redundant archive/extracted-folder pairs, stale model
weights. Markdown and HTML are pure, deterministic renders of that
struct, so producing the write-up again later never requires redoing
the analysis. The JSON Schema is generated from the Go structs and
embedded for an agent to fetch the contract before writing one:

```bash
diskwise insights schema
diskwise insights render insights.json --format md  --out insights.md
diskwise insights render insights.json --format html --out insights.html
```

### CLI (`diskwise`)

```bash
diskwise scan ~                          # index a directory tree
diskwise summary ~                       # aggregate stats
diskwise hotspots ~                      # known hits + large unexplained dirs
diskwise opportunities ~ --action safe_delete
diskwise savings ~                       # reclaimable bytes by tier
diskwise report ~ --format html --out report.html
```

Every command accepts `--json` for scripting, and `scan`/`rescan` show
a live terminal progress meter (`mogo/fmt/progress`) while the walk
runs.

## Known Limitations

- **MCP server not implemented** — `cmd/diskwise-mcp` is a skeleton binary; no tools are registered yet (Phase 5, RMI-DISKWISE-021 onward).
- **No developer-detector depth** — Xcode DerivedData/Archives/simulators, Docker image/volume/build-cache breakdown, and per-project attribution are not yet split out (Phase 4).
- **No findings persistence** — findings aren't tied to a specific scan run or invalidated on rescan yet (RMI-DISKWISE-020).
- **No duplicate/near-duplicate file detection** — recognizing byte-identical or near-identical files across directories (e.g. a backup archive next to its extracted folder) currently requires manual investigation or an LLM agent authoring an `insights.Report`, not a built-in detector.
- **Discovery only** — DiskWise does not delete anything, integrate with Trash, or execute any of its recommendations; that's an explicit V1 scope boundary, not a bug.
- **macOS only** — `platform/` uses Darwin-specific syscalls; Linux is unphased backlog.
